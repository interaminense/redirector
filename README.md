# Redirector

A Chrome extension (Manifest V3) that redirects URLs based on user-defined rules and optionally enables CORS on the affected responses.

Inspired by [Redirector](https://chromewebstore.google.com/detail/redirector/jegbdohdgebjljoljfeinojeobdabpjo). Adds a per-rule **Allow CORS** toggle that injects permissive `Access-Control-Allow-*` response headers, which is useful when redirecting API endpoints.

## Features

- Wildcard patterns with capture groups: `http://example.com/*` → `https://example.com/$1`
- Regex patterns: `https://old\.site/article/(\d+)` → `https://new.site/a/$1`
- Per-rule CORS allowance (adds `Access-Control-Allow-Origin: *` etc. to response headers)
- Per-rule enable/disable toggle
- Global on/off toggle in the popup (keeps storage intact)
- Options page with full CRUD, import/export JSON, and per-rule resource type filtering
- Active-rule count shown as a badge on the toolbar icon

## Install (unpacked)

1. Clone or download this directory.
2. Generate the placeholder icons (once):
   ```bash
   node scripts/generate-icons.mjs
   ```
   (Already included in git, but regenerate if you want to customize them.)
3. Open `chrome://extensions`, enable **Developer mode** (top right).
4. Click **Load unpacked** and select this project's root folder.

The extension appears in the toolbar. Click its icon for the popup; right-click → **Options** for the full rule manager.

## Rule format

Rules live in `chrome.storage.local` under the `rules` key. Shape:

```ts
type Rule = {
  id: string;                           // uuid
  description?: string;
  patternType: "wildcard" | "regex";
  pattern: string;                      // e.g. "http://example.com/*" or raw regex
  redirectTo: string;                   // uses $1, $2... for captures
  allowCors: boolean;                   // add Access-Control-Allow-* headers
  enabled: boolean;
  resourceTypes?: string[];             // defaults to main_frame + sub_frame + xmlhttprequest
};
```

Export/import JSON uses `{ "rules": Rule[] }`.

## How it works

- The service worker watches `chrome.storage.local`. On every change it rebuilds the active `declarativeNetRequest` dynamic rules and swaps them atomically via `updateDynamicRules`.
- Wildcard patterns are converted to anchored regex (`*` → `(.*)`), substitutions use DNR's `\1..\9` style (we rewrite `$1..$9` for you).
- When **Allow CORS** is on, we emit a second DNR rule with `action.type = "modifyHeaders"` that sets the `Access-Control-Allow-*` response headers on the same URL match.

## Testing

1. **Wildcard redirect:** add rule `http://example.com/*` → `https://example.com/$1`. Visit `http://example.com/foo` and confirm HTTPS redirect.
2. **Regex redirect:** add regex `https://old\.site/article/(\d+)` → `https://new.site/a/$1`. Visit `https://old.site/article/42` → should land on `https://new.site/a/42`.
3. **CORS:** add rule targeting an API (e.g. `https://api.example.com/*` → `https://api.example.com/$1` with **Allow CORS** on). From any page's DevTools console:
   ```js
   fetch("https://api.example.com/data").then(r => r.json()).then(console.log)
   ```
   Before the rule: blocked by CORS. After: succeeds, and the Network tab shows `Access-Control-Allow-Origin: *` on the response.
4. **Toggle global off in the popup:** no redirects fire; turn it back on and the rules resume.
5. **Import/export:** export, delete all rules, import back — state restored.

## Limitations

- Uses `chrome.storage.local` (not `sync`) because `sync`'s 8KB-per-item limit is tight for a rules list.
- Firefox isn't supported (DNR details diverge between Manifest V3 implementations).
- CORS header injection won't help with requests the browser already cached; hard-reload or add `cache: "no-store"` while testing.

    storage.js
